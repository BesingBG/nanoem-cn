渲染器
==========================================

.. important::
    macOS Mojave 之后 OpenGL 已被弃用，因此如果 Metal 可用，会自动选择 Metal。

更改 nanoem 使用的渲染器。根据操作系统，可用的渲染器不同。

.. csv-table::

  **渲染器**,**MacOS 可用？**,**Windows 可用？**
  OpenGL,✅,✅
  Metal,✅,❌
  DirectX11,❌,✅

macOS 版默认使用 Metal（如可用），Windows 版默认使用 DirectX11。

颜色格式
==========================================

显示视口显示使用的格式。默认值为 RGBA8。

- RGBA8
- RGB10A2
- RGBA16F

RGB10A2 和 RGBA16F 用于 HDR，需要支持 HDR 的外部显示器才能正确显示。
另外，选择 RGBA16F 时渲染速度会比 RGBA8 慢。

仅当 macOS 版且选择 RGBA16F 时，使用的色彩空间会切换为 Display P3。

编辑时帧率
==========================================

.. note::
    项目播放时适用菜单「项目」中的「帧率」。

选择非播放状态下的 FPS。

- 自动

  - 根据情况在 30FPS 或 60FPS 之间切换处理

    - 连接电源时为了提升性能，以 60FPS 处理
    - 电池驱动时为了降低消耗，以 30FPS 处理

- 30FPS
- 60FPS
- 无限制

  - 垂直同步被禁用，以最大输出超过 60FPS 处理
  - 非常消耗资源，非必要请勿使用

高分辨率视口
==========================================

.. note::
    此设置面向采用高分屏但渲染性能相对较差且没有外置 GPU 的 Intel 版 MBA/MBP。
    虽然视口渲染会变粗糙，但可以降低渲染负载（尤其在使用后期效果时效果明显）。

选择高分辨率视口的设置方法。这只是启动时的设置，可以通过「:ref:`88592664-60C0-40B8-B14A-06983999A95D`」切换。

- 启动时自动设置

  - 启动时如果选择了外置 GPU 则启用，否则禁用
  - 初始设置适用「启动时自动设置」

- 始终启用
- 始终禁用

  - 29.0 以下适用相当于「始终启用」的处理

启用模型渲染负载分散
==========================================

.. note::
    设置生效需要创建新项目或先保存一次再加载。

将模型渲染时由 CPU 计算的高负载处理（蒙皮）分散到 GPU。启用后可以减轻 CPU 负载。
但根据 GPU 的不同，计算结果可能不符合预期，导致模型显示异常，此时需要禁用。

负载分散仅适用于模型的蒙皮，附件和模型的物理模拟不适用。
此外，以下情况无论「:ref:`D1BF8CFD-152D-4D1C-8B23-1FC6A4EBF391`」的状态如何，全部由 CPU 计算：

* 使用包含一个以上软体的模型时

  * 原因是刚体以骨骼为单位处理，而软体以顶点为单位处理，两者冲突，难以获得加速的好处
  * 可以将仅由软体构成的模型分开，使用「:ref:`7A2F7651-1FF4-4669-861B-3A687D468E31`」来一定程度上解决

* 「:doc:`model`」模式下

  * 如果模式切换前已启用，模式结束时从禁用恢复为启用

初始值为禁用。

保存时的文件路径设置
==========================================

.. note::
    文件路径指以下类型的已加载文件的路径。因为它们不包含在项目文件内容中。

   * 模型
   * 附件
   * 已分配材质的效果

更改以 nmm 格式保存时项目内保存的文件路径的设置。

初始值为相对路径，但 29.2.0 及之前的版本以绝对路径保存，
加载该版本保存的项目时，绝对路径会成为默认值。

绝对路径
------------------------------------------

以不依赖项目文件保存位置的完整路径保存。

优点：即使移动项目文件本身也可以加载。

缺点：例如通过在线存储保存并同步到其他机器上运行时，若路径不完全相同则无法加载。
另外，移动加载的模型或附件后同样无法加载。
此外，根据保存位置，构建完整路径时通常会包含用户文件夹名，容易暴露个人信息，不适合文件交接。

相对路径
------------------------------------------

.. caution::
    即使设置为相对路径，如果无法解析相对路径，则会以绝对路径保存。
    这在 Windows 上适用于加载位置与项目保存位置在不同驱动器的情况。

以项目文件保存位置到文件的相对路径保存。

优点：例如通过在线存储保存并同步后可以在其他机器上运行。

缺点：移动项目文件本身时，已加载的模型和附件也必须同时移动。
另外，移动已加载的模型或附件后同样无法加载。
