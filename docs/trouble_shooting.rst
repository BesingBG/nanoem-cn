==========================================
故障排除
==========================================

使用 nanoem 时遇到问题的回答汇总。非故障类的常见问题请参考「:doc:`faq`」。

.. _0ACEC098-CB5E-40E2-99C5-01DB3BCBE080:

nanoem 打不开、无法启动
=======================================================

.. important::
    使用 macOS 10.12 时已确认启动后立即崩溃的问题，如有可能请升级到 macOS 10.13 及以上。
    此问题已在 29.1 及之后修复。

启动时出现警告对话框，请查看「`在 Mac 上安全地打开 App <https://support.apple.com/zh-cn/HT202491>`_」的「如何打开未公证或来自未识别开发者的 App」。

没有对话框但无法启动时，可能是启动时所需文件夹的访问权限不正确。详情请参考以下内容：

- `Mac OSX 突然软件无法启动时请检查访问权限 <http://otowacreation.co.jp/archives/453>`_
- `文件或应用程序突然打不开！<https://dekiru.net/article/442/>`_

如果仍未解决，可能是使用的 macOS 次要版本过旧。请通过软件更新更新 macOS 次要版本。

- `更新 Mac 的软件 <https://support.apple.com/zh-cn/HT201541>`_

音频无法加载或没有声音
=======================================================

.. important::
    31.5.0 修复了 WAV 以外的音频可能无法加载的问题，并增强了音频加载时的错误检测。

    如果没有错误提示，请确认「`Mac 扬声器没有声音 <https://support.apple.com/guide/mac-help/mchlp1439>`_」。另外，请检查是否处于静音状态。

音频无法加载的情况（macOS 版）：

* 请确认是否可以用 iTunes 或 QuickTime 加载

  * 如果这些软件也无法加载，则 nanoem 也无法加载，请检查音频文件

* 如果 iTunes 或 QuickTime 可以加载但 nanoem 无法加载，请先将音频转换为 wav (PCM) 格式再加载到 nanoem

音频已加载但整体没有声音的情况：

* 其他应用程序有声音但 nanoem 没有时，请确认 :ref:`8DF11AFA-D8D1-4A15-B8E7-B9BBB246C7FD` 的音量是否为 0%，然后重新启动 nanoem
* 包括 nanoem 在内的其他应用程序也都没有声音时，请重新启动 Windows/macOS

偶尔出现神秘的爆音
=======================================================

macOS 上已报告启动数小时后、在加载音频的状态下偶尔出现爆音的问题，但截至 2021/7/14 原因不明。如果长时间工作，请采取以下措施：

* 执行「:ref:`BCE5BB55-78D2-4B89-876F-85BA69E6022C`」
* 重新启动 nanoem

背景视频无法加载
=======================================================

macOS 版请确认 QuickTime 是否可以加载。如果不是 QuickTime，请用 `VLC <https://www.videolan.org/vlc/>`_ 或 `IINA <https://iina.io>`_ 确认。
如果 QuickTime/VLC/IINA 都无法加载，很可能视频本身未正确识别。

加载时崩溃时，转换为 avi 格式可能会切换内部使用的实现，从而可能加载成功。

项目无法读取了
=======================================================

.. important::
    31.5.0 之后，nmm 格式在项目文件加载时如果部分文件未能加载，会弹出对话框显示哪些文件未能加载。

    25.0.0 之后，如果找不到音频或视频文件，不再报错而是简单地忽略加载。
    因此，如果音频或视频未被加载，可能是原始文件因某种原因找不到。

请使用 `bowlroll <https://bowlroll.net>`_ 或其他上传工具将项目文件整套上传，并以仅本人和开发者可见的形式 [#f1]_ 在
:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。
会尽可能处理，但根据项目文件的状态，有时可能无法解决。

项目无法保存
=======================================================

.. important::
   - 在骨骼或形态已移动但关键帧未注册的状态下尝试保存项目时会出错。
   - 31.0 之前，加载现有运动后尝试保存时，有时会出错无法保存，或只保存了第一个关键帧。此问题已在 31.1 修复。
   - 26.0 之前，删除模型或附件后保存时必定失败。此问题已在 26.1 修复，如果在 26.1 以下继续使用，请不要删除模型或附件。

出现「请确认保存目标是否正常」的错误时，可能由以下原因导致：

- 是否触及上述「重要」项
- 保存目标的存储容量是否不足
- 是否正在保存到只读位置

第二种情况请使用 `GrandPerspective <http://grandperspectiv.sourceforge.net/>`_ 等工具删除不需要的文件，确保存储容量。
第三种情况可通过更改保存目标（例如桌面）来尝试保存。

如果这些方法仍无法解决，macOS 用户请通过「诊断 Mac」确认 Mac 本身是否正常。

如果以上都不适用，请确认使用的版本是否为最新版，并说明发生什么问题导致无法保存后，
在 :ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。

模型显示不正确
=======================================================

.. important::
    需要先判断是否为 nanoem 的渲染问题，请先按「:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D`」联系，而不是联系模型作者。

    但仅以个人用户身份确认，如果模型存在分发限制，可能无法调查模型。

.. important::
    33.0 开始增加了「:ref:`D102480C-FFFB-43BA-9561-291E1AF4255B`」。如果出现显示问题，请执行此功能确认。

如果全部或部分显示为白色，可能是模型的纹理未正确加载。
此时请先退避出问题的模型，根据需要重新下载模型，重新解压 zip 等压缩文件。

macOS 版可能因 zip 解压时文件名乱码导致模型显示不正确。此时请使用专用应用程序，如「:ref:`0C54A757-1FA3-4CC9-B33E-E9362B69A25B`」所述。

其他情况下的部分显示不正确，请在 :ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。
因为原因多种多样，无法给出单一的解决方案。

此外，如果出现以下情况：

- 加载模型后只显示骨骼
- 画面全黑

可能为渲染错误，但根本原因不明，没有解决方案。作为应急措施，请按以下顺序尝试：

- 重新启动 nanoem
- 如果不行，重新启动 Mac

  - 启动后，除重要程序外，请关闭所有常驻应用程序
  - 使用时不要启动 nanoem 以外的应用程序

加载模型后崩溃
=======================================================

请取消勾选「设置」的「全局设置」中的「启用模型渲染负载分散」，然后加载模型。

如果仍然崩溃，请提供崩溃的模型信息（如能确定发布来源请附上位置）并在
:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。

模型腿部抖动
=======================================================

这是 IK 的规格。尤其是当运动来源模型与目标模型身高差较大时，无法找到预期位置，现象会更加明显。请采取以下方法处理：

* 使用「编辑」的「:ref:`54256F37-C4E0-4642-9AB4-8720FACBE207`」进行修正
* 从「:ref:`E6F3DE0F-97F9-4515-ABC0-58B8999A9E70`」选择目标 IK 骨骼，点击 `Off` 后按「注册」

  * 注册后重新旋转抖动的 IK 链接骨骼，然后从骨骼面板注册关键帧

    * IK 链接骨骼在骨骼选择画面中以黄色显示
    * IK 骨骼在 Off 状态下即使移动也不起作用，无需移动

加载附件后没有任何显示
=======================================================

如果附件文件的内容全部挤在一行中，由于实现原因 nanoem 无法正确解析，即使加载也不会显示任何内容。

解决方法：使用 Metasequoia 导入文件后以其他文件名保存，
或使用 `homebrew <https://brew.sh>`_ 等工具安装 `assimp <http://assimp.org>`_ 后通过以下命令行进行转换。

.. caution::
    Blender 仅支持通过插件导出，此外在 2.80 之后已不支持

.. code-block:: none

   # homebrew の場合
   brew install assimp

   # input.x 是 nanoem 无法加载的附件文件路径
   # output.x 是导出目标，文件名任意
   assimp export /path/to/input.x /path/to/output.x

加载附件或效果后崩溃
=======================================================

请提供崩溃的附件或效果信息（如能确定发布来源请附上位置），并在
:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。

.. _087A9DEC-BE10-4162-8D08-293B6936ADCC:

每次创建新项目时都显示错误
=======================================================

可能是音频输出初始化失败。请确认其他应用程序是否有声音。
另外，即使出现错误也可以播放，但加载音频后不会有声音。

视频导出时崩溃
=======================================================

32.0 以下已确认启用抗锯齿时会崩溃的问题。
如果使用 32.0 以下版本，请升级到 32.0 或禁用抗锯齿后再导出。

32.0 及以上在某些情况下也可能在启用抗锯齿时崩溃。
此时请使用抗锯齿效果替代，并禁用抗锯齿后导出。

视频导出时音画不同步
=======================================================

34.1 以下满足以下条件时，即使从中途开始导出，也会从音频开头开始的问题。

* 已加载音频
* 视频导出设置中起始帧设置大于 0
* 取消勾选了「启用操作系统自带编码器」

34.1 及之后已修复。34.1 以下请将起始帧设置为 0 导出视频，然后通过视频编辑调整。

此外，在以下条件下导出的视频在某些播放器上可能出现卡顿：

* 使用 ``plugin_lsmash`` 导出
* 使用了采样位数为 24bit 且频率为 48000Hz 的音频

如果符合以上情况，请使用 ``plugin_ffmpeg`` 导出，或将音频转换为采样位数 16bit 及频率 44100Hz。

视频导出后输出异常（例如全黑）视频
=======================================================

如果勾选了「启用操作系统自带编码器」导出，请取消勾选，改为从 Plugins 栏选择 ``plugin_lsmash`` 进行视频导出。

如果 :ref:`9816D13E-ADA9-44D9-A869-1F61537D7753` 为 OpenGL 且可用时，切换为 Metal 有时可以解决。

如果仍未解决，请升级 macOS 版本，如果还不行，只能放弃 nanoem 的视频导出，使用 QuickTime Player 的屏幕录制。

视频导出时出现播放时没有的丢帧
=======================================================

.. important::
    31.5 开始在视频导出设置画面中增加了「启用帧偏移抑制」。如果已禁用，请启用。

已确认在启用「启用操作系统自带编码器」时会触发此问题。
但技术规格上原因不明且无法修复，请采取以下方法处理：

- 使用 :ref:`087A9DEC-BE10-4162-8D08-293B6936ADCC` 中的方法处理
- 通过视频编辑去除丢帧部分，根据前后帧进行补完

窗口画面显示为蓝色
=======================================================

使用 OpenGL 渲染器时，由 nanoem 端的错误引起。如果遇到请在
:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 报告。

如果使用 Metal 渲染器则不会发生，因此不报告的话很可能被搁置。

加载相机运动后角度 X 轴反转
=======================================================

.. important::
    33.0 已修复。32.0 及之前保存的项目将在加载时自动修正。

这是 32.0 及之前的问题。请选择「编辑」>「相机」>「打开修正对话框」，将「角度」的第一项的 ``* 1.00`` 改为 ``* -1.00``，然后点击「OK」执行。

物理模拟中发生穿透
=======================================================

物理模拟部分仍在调整中，因此容易发生穿透（尤其是裙子）。由于物理模拟的规格所限，无法完全防止。请尝试以下方法：

- 用相机遮挡穿透部分

  - 最简单的方法，但可见部分会减少

- 调整刚体或关节的参数

  - 从设置画面启用模型编辑功能后，通过菜单的「编辑」>「打开模型编辑窗口」可编辑「刚体」和「关节」的参数
  - 但操作和调整非常困难，请仅在必要时使用

- 取消勾选 :ref:`54B1F974-2B39-4472-B6F5-EAB40FDCC4F7` 的「物理」复选框后注册

  - 请参考「:ref:`166E84B9-236D-41F4-9FD0-CCA457D28076`」
  - 26.0 之后实现的功能，取消勾选「物理」复选框后注册的关键帧将禁用物理模拟
  - 由于存在启用和禁用之间的插值规格，处理较困难，但这是控制物理模拟切换的唯一手段

移动相机时自身阴影有时会消失
=======================================================

.. important::
    29.0 以下自身阴影的计算方法存在问题，修复后发生频率已降低。

这是自身阴影机制的限制导致的规格，并非错误。
如果发生，请切换模式或调整自身阴影的有效距离，然后注册自身阴影的关键帧。

如果使用配备外置 GPU 的 Mac，也可以使用 ExcellentShadow 等更高级的自身阴影效果。
虽然无法完全消除，但可以减少发生。效果 README 中也有说明，应用后运行会变慢。

解压 zip 后文件名乱码
=======================================================

请使用 `The Unarchiver <https://itunes.apple.com/jp/app/the-unarchiver/id425424353>`_ 等应用程序解压。这是因为 zip 内的文件名编码在日文版 Windows 以外的系统无法正确识别。

MMD 相关的 zip 大部分由日文版 Windows 制作，因此在日文版 Windows 上没有问题，
但在非日文版 Windows 及 macOS 上处理时，由于上述原因会导致乱码问题。

如何分离时间轴和视口？
=============================================================

33.0 之后可以通过「:ref:`5BB93875-36E2-42A2-B232-BD61D8FD131D`」进行分离。
更早的版本只能调整时间轴和视口的比例大小。

但并非像 MMD 那样作为独立窗口分离，而是作为应用程序内的窗口分离，因此无法将窗口拖出外部。

设置外部父级后关联到意外的模型
=============================================================

外部父级的目标模型按名称关联，因此如果项目内模型名称重复（多次加载同一模型时会发生），外部父级将设置给第一个模型。

如果模型名称重复，请参考「:ref:`62EB4D2C-F84D-4B9A-A942-4216F524C01A`」更改非目标模型的名称。

反复暂停后播放时会卡顿
=============================================================

.. note::
    即使不加载音频也会发生此问题。因为内部会加载静音音频。

这是由于音频同步修正处理的影响。反复暂停会导致音频偏移增大，每次都会强制触发音频同步修正处理。

解决方法：请选择屏幕右下角的停止而非暂停菜单。修正处理会重置，卡顿的现象将消失。
但停止后再次反复暂停时会复发。此外，不提供禁用音频同步修正处理的方法。

部分字符显示为「？」
=============================================================

nanoem 使用内置字体源暎GothicP `源暎ゴシックP <https://okoneya.jp/font/genei-gothic.html>`_，因此该字体未收录的字符无法显示。这是规格。

此外，由于内部处理原因，不支持 ASCII 及日文以外的字符显示。

.. _F6684DC6-51A9-49DB-B4E8-7C1CF8BAF23B:

加载从 VRM 转换的模型后只显示骨骼
=============================================================

这是 24.x 系之前存在的、由 VRM 转换时附带的着色器引起的问题。请采取以下方法处理：

- 使用 25.0.0 及以上版本
- （继续使用 24.x 系及以下时）删除或替换附带着色器

  - 替换时请将 `half2` `half3` `half4` 分别替换为 `float2` `float3` `float4`
  - 无论哪种方式，卡通渲染显示仍不正确，会遗留颜色不符合预期的问题

    - 卡通渲染显示错误的问题已在 25.0.0 及以上版本中解决

macOS 10.15 及以上显示「键盘输入监控」确认对话框

出现 OSStatus returns 560558962
=======================================================

.. note::
    24.0 的错误，加载 WAV 以外的音频时会发生。已在 24.1 修复。

这是 nanoem 使用的 macOS AVFoundation 的错误。

请将音频转换为 WAV (PCM) 后加载。另外，请确认引发问题的音频的频率
（采样率）是否在 8KHz 到 192KHz 范围内。
如果仍未解决，请按 :ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 的步骤报告。

出现 OSStatus returns 2003332927
=======================================================

同样是 AVFoundation 的错误，但原因不明，请按
:ref:`37420267-8E5A-41EA-A159-FFF490DF1D8D` 的步骤报告。
